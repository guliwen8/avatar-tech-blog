# 公众账号、访问权限与咨询

承接结构对比报告第三阶段，沿用现有 Next.js、SQLite 与浅色页面，不引入新服务。账号阶段未包含真实支付、邮件验证/邮件重置、附件与 Agent；后续私有文件和咨询截图的设计及限制见《私有文件说明》。

## 数据与认证

公众账号、公众会话、频率限制、咨询和回复使用新增表，原管理员 users/sessions 和原订单保持不变。公众 cookie 使用 avatar_reader_session；会话随机令牌只在数据库保存 SHA-256 哈希，服务端七天到期。密码使用现有 bcrypt 依赖，最多 72 字节。注册不授予会员；管理员确认开通后设置到期时间。

公众请求不能使用管理员 API。新状态变更接口校验同源，登录及咨询有持久化频率限制；退出和重置密码撤销会话。登录失败使用统一错误。前台修改密码必须验证当前密码。找回采用人工核验，不声称已发送邮件。

## 内容策略

posts.details.access 为 public/login/member，缺省 public。保持旧文章公开，不将历史 VIP 角标自动解释成付费门槛。元信息始终过滤受限播放/下载/仓库链接；详情在服务端决定是否渲染正文、目录、正文外链与专用资料。草稿仍不可公开读取。

公众账号状态与权益在每次请求时重新读取，到期、撤销立即影响下一次请求。付费文件本身仍需来源网站鉴权；隐藏链接不等于对公开第三方媒体提供 DRM。

## 咨询

任何已登录读者可提交文本问题，不扣费、不扣积分。每条记录绑定服务端识别的账号；只能由本人查询和补充，管理员可回复、关闭或重开。状态为 open/replied/closed。用户无法自行修改归属、状态或回复角色。关闭后须由管理员重开，或创建新咨询。旧浏览器草稿由用户主动导入，不自动读取到另一账号。

## 页面与后台

/login、/register、/account、/forgot-password；服务与隐私说明在 /terms 和 /privacy。主导航增加独立账号入口，保留八项内容导航。/consult 登录后显示受理与历史，匿名保留本地草稿。

后台新增读者与会员、咨询管理；后台文章可选择正文权限。套餐页改为咨询开通，禁止公众模拟支付，不根据模拟订单授予任何权益。

## 验证要求

- 四种身份对公开、登录和会员正文分别验证，包含 HTML 和 RSC 响应及列表元数据的地址泄漏检查。
- 注册、登录、改密、退出、会话过期；公众账号不能访问管理 API。
- 管理员开通/撤销会员，旧会话即时反映权益变化。
- 用户 A 提交→管理员回复→A 查看/补充→关闭；B 无法查询或回复 A 的记录。
- 无效来源、无效数据、频率限制、草稿不可见与历史认证循环回归。
- 390/897/1440px 布局、样式和脚本资源以及重复刷新。

所有变更先在本地副本验证，再另行备份和部署 NAS；本批不自动推送或部署。
